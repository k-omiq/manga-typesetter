1: CONFIRMED — `step()` updates the in-memory undo/redo stacks and invokes `markUnsaved()` (scheduling `chapter.json` autosave after 800ms) but never calls `sink?.(entry.pageId)` or `schedule()`, so `history.json` is never scheduled for persistence upon undo/redo. If the process is killed or crashes >800ms after an undo/redo without a graceful flush, `chapter.json` contains the post-undo state while `history.json` retains the pre-undo stack, causing replay divergence on relaunch ([`src/lib/editor/history.svelte.js:315`](file:///Users/caved/dev/manga-typesetter/src/lib/editor/history.svelte.js#L315)).

2: CONFIRMED — `openChapter()` launches `openHistory()` without awaiting it ([`src/lib/library.svelte.js:1159`](file:///Users/caved/dev/manga-typesetter/src/lib/library.svelte.js#L1159)). If the user immediately switches to page 2 or makes an edit while `fsx.readTextFile()` is in flight, `openHistory()` resumes, unconditionally overwrites `doc = loaded`, and executes `loadStack(pageId, ...)` with the initial page's ID, wiping in-flight edits or loading Page 1's stack into memory while the active page is Page 2 ([`src/lib/editor/history-file.svelte.js:180`](file:///Users/caved/dev/manga-typesetter/src/lib/editor/history-file.svelte.js#L180)).

3: CONFIRMED — `closeHistory()` performs `const mine = dir; await flushHistory(); if (dir !== mine) return;` ([`src/lib/editor/history-file.svelte.js:281-287`](file:///Users/caved/dev/manga-typesetter/src/lib/editor/history-file.svelte.js#L281-L287)). When closing a chapter and immediately reopening the same chapter while the close flush is in flight, `openHistory()` sets `dir = pathA`; when `closeHistory()` resumes, `dir !== mine` evaluates to `false` (`pathA !== pathA`), triggering trailing cleanup that sets `dir = null` and calls `resetHistory()`, wiping the active undo stack and permanently disabling history saves for the new session.

### Priority Summary
- **P1 (Findings 2 & 3):** Async lifecycle race conditions in [`history-file.svelte.js`](file:///Users/caved/dev/manga-typesetter/src/lib/editor/history-file.svelte.js) that corrupt the active page's undo stack on rapid page turns/edits during chapter load or permanently disable undo persistence when reopening the same chapter.
- **P2 (Finding 1):** Missing debounce sink notification in [`history.svelte.js`](file:///Users/caved/dev/manga-typesetter/src/lib/editor/history.svelte.js) causing on-disk document vs. history journal divergence if the process terminates abnormally after an undo/redo.
